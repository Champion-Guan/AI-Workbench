如果旧工具停在“需要同一 Chrome 配置中已加载 1.0.1 版工作台扩展”，
停止点在浏览器数据复制之前，不能把它当作下载或原数据丢失。
请使用 v1.0.11 发布页的完整一键迁移工具，保留原 v1.0.7 服务运行。

`browser/managed-workbench` 目录。请在原来使用工作台的 Chrome 配置中
开启开发者模式、加载该目录（已有扩展则重新加载/更新至 1.0.2）。
浏览器首次授权不能由脚本静默代替。加载后工具自动继续，不必重下安装包。

任一失败仍保留旧数据和备份，禁止清空目标存储或强杀端口。

## 一键入口

保存画布并结束生成，关闭工作台页面后，双击项目内
`scripts/迁移5174到8888.command`。其他网站和应用无需退出。
脚本没有控制台粘贴、逐步回车或手动选择安装包的步骤。

适用于 macOS Apple Silicon：已接入独立 launchd 更新器的 5174 工作台，
以及**下载 v1.0.7 解压运行、尚未接入更新器**的 5174 工作台。
并且原来保存画布的 Chrome 配置已加载本项目 1.0.1 或更新版受管理扩展。
Chrome 已退出时脚本会打开现有 Chrome，不创建新的用户数据目录；
若 Chrome 恢复了工作台标签页，则仍阻止迁移。
扩展不会读取其他网站、不更换 Chrome 数据目录，不通过本机桥传输画布或密钥；
迁移数据只在两个本机 Origin 与私人的临时备份服务间传输。
旧 1.0.0 扩展、未装扩展、其他浏览器及 v1.0.4 等更早便携版不具备自动迁移能力，
脚本会停止，不会把空配置当作迁移成功。已有的 v1.0.8 发布资产没有被改写，
本工具及新版扩展需要使用当前源码目录；不能只复制一个 `.command` 文件。

执行时自动从公开仓库 `Champion-Guan/AI-Workbench` 获取最新 Stable arm64 包，
先验证内置可信 Ed25519 签名、SHA-256、文件库存和启动协议，再开始备份迁移。
网络失败或不兼容时停止，保留原服务。维护人员仍可传入一个已下载的签名资产目录。
首次页面检查与下载后页面检查均通过，才打开扩展自己的临时迁移页；
复制并逐项验证成功，关闭临时页并再次检查页面后，才切换确切自有服务。
安装事务开始后不要强制结束终端或关机，让安装器完成健康检查或回滚。

目标 8888 已运行时直接跳过重复迁移，不读取旧 Origin、不写数据；
这只证明目标服务已运行，不代替浏览器数据校验。目标非空、端口未知占用、
校验超时、下载验签失败均停止，不清库、不覆盖、不按端口杀进程。
自动备份位于 `~/Library/Application Support/GuanAIWorkbench/backups/port8888-*`。

## Mac B 解压运行 v1.0.7 的首次接管

保留 v1.0.7 的服务运行，只关闭已保存的工作台页面。新入口自动识别缺少
`installation/current.json` 和 `updater-deployment/deployment.json` 的便携安装。
只缺一个文件、已有未完成事务或进程身份不明时拒绝接管，不猜测、不覆盖记录。

首次接管先核实 5174 唯一监听进程的用户、启动时间、Node 命令、工作目录、
v1.0.7 版本和源码哈希，拒绝不同私人数据目录。随后下载验签、备份私人文件，
通过原 Chrome 配置的扩展导出 5174 并 copy-once 恢复到 8888，逐项校验。
两端页面关闭、签名运行时暂存完毕、备份哈希复核、launchd 配置无冲突之后，
才重新核实原进程并向该 PID 发送一次 SIGTERM。等待退出超时不使用 SIGKILL。
然后安装当前用户的独立更新器和 supervisor，首次启动签名工作台并健康检查。

无需输入「确认首次接管」或另外手动停止旧服务，双击入口就是本次维护操作。
原 Chrome 首次加载扩展仍需用户本人授权，这是浏览器限制，不能静默绕过。
新增的接管分支不在已发布 v1.0.9 包里；应使用本次独立迁移工具或后续新发布包，
不要只把新 `.command` 放进旧包（它依赖同套脚本和服务模块）。

失败恢复分界：停止旧服务之前失败不影响旧服务；首次新服务启动失败时安装器
保留事务、旧目录及备份。若提交状态不明确，不自动另启动旧服务造成双实例，
终端提供旧便携目录和备份路径，核实新服务已停止后可从旧目录恢复 5174。
8888 已复制的数据保留，不能删除它后盲目重试。断电或提交后激活异常需要
按现有签名首次接管事务进行恢复，不代表迁移成功。

本次补齐验证：新增 8 项首次接管专项测试全部通过，包含实际 macOS 临时
Node 监听进程的身份核验和正常停止；旧 PID 变化、页面重开、超时、残缺安装
记录、不同私人根和备份篡改均拒绝。原全量回归首轮 575/576 通过，唯一失败为
测试使用 `/var` 而真实路径是 `/private/var` 的断言，已改为 realpath 比较并重跑
新增专项及迁移/页面回归通过。Playwright 独立浏览器、随机端口、无安装记录
的实际便携模式备份与恢复通过，包含 localStorage、IndexedDB、图片 Blob，
私人备份复核通过。Lint 0 错误、4 个既有警告，源码秘密扫描无发现。
这些结果不代表 Mac B 实机已迁移，也没有重启 Mac A 或发布新 Stable。
