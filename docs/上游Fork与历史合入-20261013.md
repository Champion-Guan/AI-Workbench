## 后续更新约束

不能因已经关联历史就直接执行普通上游整仓合并。`ours` 将该基线标记为已合并，但没有应用其文件变化；普通 merge 不会自动完成目录映射，可能遗漏此前差异或添加重复目录。

每次先 `fetch upstream`，在独立分支对比记录的上游基线与新提交，再按 `web/src → src/canvas`、配置及 public 的实际对应关系制作补丁。对于当前已存在的差异，仍需结合本地定制逐文件评估。验证画布、产品、主题、数据与生成流程后才合并源码；更新本记录的基线时说明究竟是历史关联还是源码已采用。

GitHub 的 fork 网络仅属于新建的 `Champion-Guan/infinite-canvas`。原 `AI-Workbench` 仓库不会因为 Git 合并而自动变成 GitHub fork；如需要更换正式仓库身份，需另行规划 Releases、更新渠道和 URL 兼容，不能静默替换。
