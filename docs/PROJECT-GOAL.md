## 最终目标

Mac A 使用当前最新源码开发并测试，由用户主动确认发布 GitHub 私有仓库的正式 Stable Release。Mac B 的工作台自动检测、后台下载、验证签名与完整性，在所有任务和同步安全空闲后安装，重启本地服务并健康检查；失败时回滚到可用版本。

两台 Mac 的 API Key、Token、代理节点与订阅、服务器配置、WebDAV 凭据、画布、图片视频、任务记录和偏好独立保存。任何更新不得清空这些数据、用默认配置覆盖已有配置、变更浏览器访问 Origin，或把 Mac A 的个人配置带到 Mac B。

## 不可突破的约束

1. 以当前工作目录源码为准，不以 v1.0.3 旧个人包代替最新代码。
2. 先备份、再改造、逐阶段验证；未通过验收不得宣称进入下一阶段。
3. Stable Release 必须由用户主动批准。普通 Push、个人迁移包、Draft、Prerelease 不触发正式安装；禁止自动降级。
4. 更新认证和 AI 密钥不进入前端构建、Git 历史、日志或 Release；每台 Mac 独立授权，优先 Keychain。
5. 代码版本目录与私人运行目录分离；保留既有浏览器存储，不假设数据全部在文件数据库。
6. 安装器独立于 Web 服务，用户态 launchd 管理，受限本地通信，不向网页开放任意命令执行。
7. 每次安装须明确确认画布已保存、生成/Agent/WebDAV全部结束，关闭所有工作台页面；浏览器与其他网站无需退出。原生未决任务、坏记录、保存失败和未知所有权仍禁止安装。确认不能清除证据，不把页面关闭当作远端终态。完整自动库存、工作台开窗无感安装留作后续增强。
8. Web 应用更新与 Mihomo 核心更新分离，不覆盖私人代理配置或清空订阅。
9. 下载必须验证内置可信 Ed25519 公钥签名的清单及包 SHA-256，不信任同源下载的裸哈希。
10. 保持已有工作台视觉和操作习惯；复用现有版本 Hook、设置与弹窗。

## 最终验收

- Mac A 发布正式版后，Mac B 启动检查或运行期间每 6 小时检查可发现新版本，设置支持手动检查。
- 默认自动检查、自动下载；自动安装可关闭，且必须通过空闲屏障。
- 忽略普通提交、Draft、Prerelease、旧版本和版本/架构不匹配的包。
- 签名不可信、下载中断、包损坏、认证失效、限流、断网、空间不足时保留当前版本和数据。
- 正在生成、Agent 运行、写入或 WebDAV 同步时不切换；进入切换屏障后不允许新业务任务插入。
- 新版本无法启动、健康检查不匹配或切换异常时恢复原可用版本；有不可逆迁移则停止，保留备份，禁止冒险回滚数据库。
- 后续仅支持 Apple Silicon（macOS arm64），不再构建、签名、发布新的 Intel 包；保留历史 v1.0.4 双架构资产和兼容验签，不修改已发布版本。不以打包成功代替可运行测试。
- 在两台实体 Mac 验证配置、浏览器 Origin、画布和生成文件更新前后完整，各自修改互不覆盖。
- 私人凭证、个人迁移包和运行数据不存在于源代码提交、历史、Actions 日志或 Stable 包。
- 不要求 Apple Developer 账号、Developer ID 签名或 notarization；不因缺少这些服务阻止 Stable 发布和本机更新。
