# 公开仓库、8888 端口和安全脚本

仓库：<https://github.com/Champion-Guan/AI-Workbench>，公开，GitHub Actions 保持停用。
新启动默认 `8888`；`localhost:8888` 重定向到 `127.0.0.1:8888`，不产生两套浏览器存储。
私人数据目录和 Keychain 账户名称保持不变，仓库改名不会创建一套空私人配置。
历史正式签名清单仍可验证，只兼容本项目已知旧仓库名，不接受任意仓库作为别名。
公开更新检查和下载不需要 GitHub Token，已有私人授权保留且不发送到公开下载请求。

## 旧地址的数据

浏览器按 Origin 保存 IndexedDB/localStorage。修改端口不等于迁移这些数据。
生产旧服务没有因源码修改被强制停止。新代码上线前必须先备份、迁移并验证。
新代码提供 `/local-app/port-migration`，同一电脑、同一个浏览器配置中执行：

1. 保存信息、关闭其他工作台页面；在旧 Origin（5174）运行新版代码的迁移页，导出完整浏览器备份。
2. 在空的 `http://127.0.0.1:8888/local-app/port-migration` 导入备份。
3. 导入使用 add，不 clear/delete/put；校验每项记录、Blob 字节和配置值。目标已有数据时拒绝覆盖。
4. 校验通过才打开新工作台，保留旧地址存储和备份。配额或写入失败时保留部分副本，停止，不自动清空重试。

备份可能包含私人配置，禁止上传至 GitHub。Keychain 不导出到浏览器备份。
需要在同一台 Mac 使用原有 Keychain；更换电脑需各自重新配置凭据。
旧本机安全代理 URL 仅允许绑定同一 profile 后重定向到新 Origin，不能绑定其他渠道。

## 安装策略

安装前通过现有软件更新界面告知客户保存信息，关闭 8888 的工作台页面后安装。
其他网站和应用无需退出。不再要求远端 Agent/WebDAV/Gemini 的终态证明。
不清除任务账本，也不将未完成任务标记成功。不开窗安装。
仍要求可信签名、完整性、确切自有进程、受限本机通信、原子版本切换、健康检查和回滚。
只停止更新服务所拥有的工作台 Node 子进程，不按端口杀死任意程序。

## 自定义脚本与插件

`apiKey` 是不透明的 `guan-vault:` 引用，真实密钥只在 Keychain/后端。
`baseUrl` 是对应渠道的本机代理路径。使用提供的 `http`/`request` 函数；
相对路径、完整本机路径和 OpenAI/Gemini 模板按原方式使用，后端注入真实鉴权。
外部地址、其他 profile、路径逃逸和鉴权替换拒绝。后端仍限制允许的 API 路径。
脚本/插件属于用户信任的代码，不能把同页面运行环境当作恶意插件沙箱。
不支持向脚本返回真实密钥或任意认证地址；特殊供应商接口需要增加明确的后端适配。

WebDAV、Agent、Gemini 的隔离测试不等于真实远端验证；用户不要求本次进行这些实际连接。
原功能保留，没有因暂无需求删除。
