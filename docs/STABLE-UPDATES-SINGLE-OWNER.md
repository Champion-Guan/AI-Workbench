# 单人 Stable 发布方案

2026-10-11：用户明确批准由本人作为唯一所有者发布。此文取代 PHASE4 和 NATIVE-QA 中历史的“必须独立审核人/禁止自审/受保护环境”要求，不降低签名和数据保护要求。

## 当前准入

- 仓库必须为私有 `Champion-Guan/guan-ai-workbench`，所有者固定 GitHub ID `87700227`。
- 只有该所有者可手动触发及重跑，必须从默认分支输入已有版本标签、`RELEASE-STABLE` 和审核过的完整40位提交 SHA，SHA 必须等于本次 github.sha。
- 发布工作流的 quality/publish 条件、build/publish 中的事件检查，以及签名/发布脚本自身都验证身份和批准提交。构建/签名固定 checkout github.sha；标签与根版本、产物提交、架构必须一致。
- 普通 Push/PR 只运行质量 CI；BUILD-ONLY QA 不签名、不发布。所有正式发布仍需用户主动批准具体版本。
- 不创建审批环境，拟使用仓库加密 Secret `GUAN_STABLE_SIGNING_KEY`。仅 publish job 引用；构建 job 无签名 Secret/写权限。令牌仍使用 job 限定 GitHub Token，不分发个人 PAT。
- Ed25519、公钥固定信任、SHA256、双架构原生测试、Draft 资产摘要核验和禁止降级不变。自动安装保持关闭，阶段5/6未验收。

## 明确接受的安全边界

这是单人手动确认，不是双人审批，也不是 GitHub 环境级秘密隔离。仓库管理员能修改 workflow/准入代码；仓库 Secret 可被其它恶意 workflow 引用，代码级限制不能阻止所有者账号被盗后的篡改。启用2FA/Passkey、限制其它协作者、审查工作流和依赖改动，正式私钥只放加密 Secret 与安全离线备份。不要通过聊天或命令行参数传递私钥。

当前套餐没有已验证的标签保护能力，所有者仍能移动标签；上传和发布前检查不能消除检查后的竞态。签名清单固定 commit/版本/hash，客户端不以标签名替代签名。发布后不得覆盖同一版本资产，发生不确定发布结果先人工检查，不自动删Draft或重试覆盖。
