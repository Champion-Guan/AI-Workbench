## 旧客户端的独立更新器注意事项

旧仓库过渡包解决旧客户端发现和验证新应用的问题，不等于每台旧电脑的独立 launchd 更新器已同步升级。新包中的更新管理器使用新渠道，但旧电脑 job 可能仍固定旧管理器目录；该旧管理器不认识 fork 签名身份，后续新渠道安装可能安全停止。

现有 `scripts/bootstrap-stable-updater.mjs --upgrade-manager` 是同步更新独立管理器的入口，需从已验签的 v1.0.14 目录使用其内置 Node 执行，保存并关闭工作台页面后进行，不能从任意下载源码替换已部署 job。该流程在本次隔离签名测试通过，但 Mac B 实际部署仍需按自身状态核实；不宣称仅应用升级就完成了远端电脑的管理器切换，也不通过关闭签名验证绕过旧管理器。

本轮未重跑完整长期测试套件，未覆盖 Mac B 实机整链或外部 Agent/WebDAV/Gemini 实连。发布说明的后续文档提交不改变已签名包固定 commit。
