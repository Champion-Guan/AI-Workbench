# 本机源码开发模式

Mac A 的 8888 工作台直接运行当前源码目录，私人数据仍位于原 Application Support 目录，访问 Origin 不变。客户安装仍使用可信 Stable Release。

首次切换保存并关闭工作台页面后运行 `node scripts/start-source-workbench.mjs --enable`。脚本备份私人文件和原 launchd 配置，通过主管停止确切归属的 Stable 服务，禁用其登录自动启动，再启动当前源码的后台服务；启动失败则恢复 Stable。稳定版安装目录和指针保留，不被改写。

前端 TSX 修改后执行 `npm run build:canvas && npm run publish:canvas`，刷新网页即可加载；外层 CSS/JS 直接刷新即可。Node 后端修改须在保存关闭页面后重启源码后台服务，不假装刷新浏览器会加载新的后端代码。本机源码服务不连接 Stable 安装管理器，防止发布包覆盖开发代码。其他电脑的更新机制保持不变。

后台服务采用用户态 launchd，不需常驻终端。现有源码目录 `scripts/start-macos.mjs` 检测本机源码标记后打开源码工作台。恢复 Stable 前须保存并关闭页面，停止源码 job，再启用原 supervisor/updater，运行 `scripts/open-managed-workbench.mjs`；私人数据不恢复覆盖。

GitHub 发布与本机刷新是两个独立动作。后续开发完成先更新开发资源，发布 Stable 可供客户使用；本机不再为每次前端修改安装签名包。
