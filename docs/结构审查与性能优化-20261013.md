# 本轮修复与项目结构审查

以当前源码为准，本轮针对产品切换、主题、提示词关联与交互性能做集中检查。不是数学意义上的“所有代码无 bug”证明。

## 已修复

1. 旧画布挂在归档 React 页面拥有的轮播容器中，外层重绘可能移除容器。本轮使用独立的直接子节点承载画布，不在切换时销毁后台 iframe；损失挂载时恢复可见区域。恢复挂载不是跨导航的任务恢复承诺。
2. 画布异步读取增加取消标记，过期结果不覆盖新页面。已经恢复的路由不因共享产品标题查询变化重复初始化。读取异常提示保留数据，路由渲染异常显示恢复入口。
3. 主题同步曾在主题按钮尚未挂载时提前退出；每次 DOM 变化还会重复广播和注册 iframe load 回调。现在系统主题变化统一应用，load 回调每 iframe 只注册一次；按钮已同步时不重复处理。
4. 连线使用稳定回调和 memo，未移动端点的连线减少重复渲染；保留移动端点的 Chromium SVG 重绘保护，避免重新引入扇形残影。拖动/调整尺寸时不重复提交整份项目，结束后正常保存；维护排空依然禁止拖动中确认。大规模连线的帧率提升尚需固定数据集量化。
5. 无产品页恢复模板预览和产品入口双列。整理重叠菜单放到横线下方。
6. 尺寸卡片保留原提示词与所有已填写变量，同时追加尺寸优先级及防编造要求。名称规范化只兼容大小写和分隔符，不猜测不同含义的字段。AI 校准是可选的主题标签分析，不宣称能够自动核实产品尺寸或改写所有关键词。

## 优化建议（按顺序）

| 现状与证据 | 建议 | 收益及边界 |
| --- | --- | --- |
| server/index.mjs 约 4283 行、画布 project.tsx 约 4562 行、data-contract/index.js 约 2886 行 | 分离主题/导航/任务状态模块；画布分离持久化、生成编排、选择与拖动 hooks | 更容易测试与维护；按领域逐次拆分，不一次重写存储 |
| 前端单入口约 3.9 MB，构建报告多个混合静态/动态 import | 对页面和重型弹窗按需加载，隔离编辑器、媒体工具、Agent | 降低首开和每个产品 iframe 加载成本；构建依赖须先解耦循环引用 |
| 每个缓存产品保持一套 React/AntD/状态与任务监听 | 保留有任务产品，空闲产品采用有上限缓存；长期考虑单界面与后台任务分离 | 控制内存；只有已保存且无任务时才能释放，不能为性能中止任务 |
| canvas store 一条记录序列化全部项目，每个 iframe 都有各自 store 副本 | 设计单写入者或按项目事务存储，并验证跨 iframe 并发保存 | 降低写入开销；存在陈旧副本覆盖风险，需独立并发测试与备份迁移，不能直接换存储 |
| 归档外层页面保留统计/登录/预取行为，CSP 拒绝请求及旧路由 404/405 | 将外层导航与无产品页迁到可维护源码，移除不用的联网初始化 | 减少无效请求与 DOM 观察；保留原作者标识、许可与现有功能 |
| 本地解析器和 bridge 维护重复翻译表 | 从同一可测试词典生成桥接与前端数据，增加 Excel 回归语料 | 降低翻译漂移，优先显式主题/画面意图而非整段关键词次数 |
| 提示词缺少置信度和人工确认 | 显示识别依据/待填写项，允许人工改主题；AI 分析缓存按内容哈希 | 可解释且节约费用；不能靠 AI 生成不存在的产品参数 |

充分利用 Mac 性能应优先减少主线程重复工作；图片处理、压缩与大 Excel 分析适合 Worker。生成并发应受 API 限流、内存和客户额度约束，不默认拉满。后续性能验收建议固定 100/300 张卡片、200/600 条连线和 10 个产品，以拖动长帧、切换延迟、内存、保存耗时为指标，而不是主观承诺“完全不卡”。

## 验证边界

- 隔离浏览器验证系统主题同步、两产品缓存切换、空页左右布局及可见画布高度。
- 合成生图接口延迟 15 秒：开始生成后切换到另一产品，其画布正常可见；原产品后台完成并显示 1 张图片。未付费、未操作用户真实数据。
- 尺寸优先级、缺失尺寸与变量名称规范化有行为回归测试；翻译 bridge 与前端保持一致。
- 完整回归 589 项通过，最后资源读取错误处理另通过 16 项专项；TypeScript 通过，Lint 0 错误、4 条既有警告。当前源码及历史秘密扫描通过。
- AI 校准真实远端模型未付费验收；Mac B 实机结果由所有者验证。不以模拟通过宣称真实连接验证完成。
- 最新开发资源可直接用于开发服务；实际 8888 Stable 服务仍需保存并关闭页面后安装，不能以修改源码冒充生产已更新。
