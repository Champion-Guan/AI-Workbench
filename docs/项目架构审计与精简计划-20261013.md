# AI-Workbench 项目架构审计与精简计划

审计日期：2026-10-13。源码基线：`535b602`，版本 `1.0.13`。本地审计分支：`audit/web-architecture-20261013`。

## 1. 结论与任务边界

本项目继续维护 Web 版，不开发桌面版，也不安排 SwiftUI、AppKit、Electron 或其他桌面迁移。原任务中“原生版设计继承”调整为“现有 Web 设计保护与维护参考”。macOS 上的 launchd、Keychain 辅助程序是本地 Web 服务的基础设施，不是桌面客户端，不能因为名称带 native 就删除。

当前主要问题不是存在大量已经证实无用的 React 文件，而是：

1. 旧静态网页外壳与新的 React 画布形成两套前端，路由、主题、状态和通信分散。
2. 若干功能仅隐藏入口，业务代码仍参与构建；直接删除共享目录会破坏画布。
3. 画布项目页、服务器入口、共享数据契约体积较大，职责集中，维护成本高。
4. 前端主包较大，静态导入阻碍部分功能按需加载；多画布缓存与持久化一致性需要专项验证。
5. 上游 MIT 许可证保留，但没有保留可追溯的上游提交祖先；旧网页外壳及部分资源的授权来源需要补齐。

本阶段只增加审计文档并建立本地分支，没有删除业务代码、变更依赖、迁移数据、重启服务、推送 GitHub 或发布 Release。构建输出只写入被忽略的 `src/canvas/dist`，未执行 `publish:canvas`，不会替换正在运行的页面资源。

审计覆盖 Git 与上游对比、源码入口与引用、配置和存储、脚本、锁文件、构建及选定测试。静态分析不能证明每个动态插件、旧浏览器数据或所有运行分支都已验证；报告明确区分已确认残留、条件性候选和必须保留项。

## 3. 技术架构与实际运行路径

| 层次 | 入口/目录 | 实际作用 |
| --- | --- | --- |
| 本地服务 | `server.mjs` → `src/server/index.mjs` | Node HTTP、静态页面、画布路由、受限 API、凭据、代理和更新入口 |
| 旧页面外壳 | `public/index.html`、`public/assets/_next/` | 已构建 Next 静态页面，包含工作台基础 DOM；没有对应的完整 Next 源码 |
| 外壳适配 | `src/server/index.mjs` 注入脚本、`public/assets/local-canvas/` | 顶栏、产品/工作簿、弹窗适配、iframe 管理、主题联动 |
| 跨层契约 | `src/shared/data-contract/` | 产品与画布注册、回收站、浏览器备份和端口迁移等 |
| 画布应用 | `src/canvas/main.tsx`、`router.tsx`、`pages/canvas/project.tsx` | React 19、TypeScript、Vite 7、Zustand、Ant Design、Tailwind 4 |
| 画布构建 | `src/canvas/dist` → `scripts/publish-canvas.mjs` → `public/infinite-canvas` | 构建与部署是两个步骤，部署目录是实际服务资源 |
| 本机基础设施 | `src/server/update-*`、`scripts/`、`browser/managed-workbench/` | 签名校验、版本切换、launchd、浏览器页面观测、迁移 |

外部主入口是 `http://127.0.0.1:8888`，`localhost:8888` 重定向到该 Origin。`/canvas` 回到外壳，`/canvas/:id` 加载画布 SPA。React 内部还注册首页、生图、视频、资产、提示词、设置及画布列表等路由；顶层 Node 路由并不等同于全部 React 路由，不能以直接访问 `/image` 是否成功来判断组件无用。

`router.tsx` 静态导入这些页面，因此隐藏导航不会让它们退出构建。Agent 的 `agent-site-tools.ts` 仍可导航至生图/视频路由。画布页隐藏内部顶栏，但布局仍挂载设置弹窗、移动导航和 Agent 相关组件/初始化逻辑。

核心无限画布是自有 React/DOM/SVG 实现，不是 React Flow。`node-registry` 与插件接口也服务于内置节点，因此“删除插件目录”会影响普通画布。

### 3.1 职责集中和性能风险

基线中 `src/server/index.mjs` 约 4,251 行，`pages/canvas/project.tsx` 约 4,571 行，`src/shared/data-contract/index.js` 约 2,892 行，`public/assets/local-canvas/canvas.js` 约 1,312 行。行数说明维护复杂度，不证明代码有 bug 或无用。

本轮构建主 JS 为 3,916.90 KB，gzip 1,232.57 KB；CSS 112.83 KB，gzip 19.81 KB。构建报告大 chunk，以及凭据、localForage、画布 store 同时被动态和静态导入，后者不能形成预期拆包。后续可按路由与弹窗拆分，但应先测首次进入、产品切换和拖动成本，不能仅用包大小推断卡顿原因。

缓存画布 iframe 各自持有 store 副本，而画布持久化包含聚合项目数据，需要专项验证并发保存是否发生旧副本覆盖；这是结构风险，尚不能据此宣布已复现数据丢失。连线拖动需分别分析节点渲染、路径计算、订阅范围、每帧持久化和缩略图工作，避免直接把所有组件 memo 化。

- 本地 `output/` 约 4.6 GB：包含构建、发布证据和备份，不是简单垃圾。先按保留政策归档已核实可恢复的重复产物；私人备份不能因精简源码而删除。

- `.playwright-cli` 与测试截图/日志可能包含私人数据，适合按需归档和脱敏，不上传完整用户现场记录。

## 6. npm 依赖候选

以下结论来自源码/样式引用与包声明检查，最终删除仍须在隔离安装中验证锁文件、构建和运行。类型包、隐式 CSS 引入及动态模块不以“没有普通 import”直接判无用。

| 依赖 | 证据 | 结论 |
| --- | --- | --- |
| `@codemirror/lang-json` | 未发现直接引用；现有脚本编辑器使用 JavaScript 语言包 | 第一批移除候选；验证编辑器和构建 |
| `class-variance-authority` | 未发现直接引用 | 第一批移除候选；验证公共 UI 与构建 |
| `react-router` | 没有直接 import，但 `react-router-dom` 依赖它 | 可考虑只取消直接声明，不能要求从依赖树消失 |
| `streamdown` | Agent 消息组件使用，主样式还有关联 | 只有 Agent 移除后连同样式处理才可去掉 |
| `@uiw/react-codemirror`、`@codemirror/lang-javascript` | 渠道的模型脚本编辑器使用 | 只有取消自定义脚本功能后才可去掉 |
| `@ant-design/pro-components` | providers 包装层使用 | 可研究更轻替代，但需验证主题、上下文和弹窗。其 peer 约束与 antd 6 存在兼容风险，当前安装使用 legacy-peer-deps |
| `shadcn` | `styles/globals.css` 实际引入 `shadcn/tailwind.css` | 不能按“CLI 工具”直接删；先核对并替换所需样式及许可证 |

| `antd`、`axios`、`localforage`、`zustand`、`react-query`、Radix、Tailwind、fflate | 画布、配置、API、持久化、提示词和导入导出实际使用 | 保留；瘦身应先减少使用范围，不强行替换 |

## 7. 数据与敏感配置保护

### 7.1 真实存储位置

| 位置 | 内容 | 保护要求 |
| --- | --- | --- |
| IndexedDB/localForage `infinite-canvas/app_state` | Zustand 持久化配置与业务状态 | 不改库名、key、结构或清空；留兼容读取 |
| 同库 `image_files`、`image_previews`、`media_files` | 图片、预览及媒体 | 不根据 UI 隐藏推断可删文件 |
| 同库 `image_generation_logs`、`video_generation_logs`、`prompt_cache` | 历史和提示词缓存 | 缓存与业务记录分别定保留策略 |
| localStorage | 工作簿、产品注册与标题、回收站、主题、变量记忆、引用标记等 | 精简不能改变 Origin 或覆盖旧值 |
| `~/Library/Application Support/GuanAIWorkbench/` | 私人配置、代理、runtime、安装与更新相关目录 | 不随代码清理；备份另行保护 |
| macOS Keychain | 凭据与更新授权 | 不输出、不打包、不因去 UI 删除 |
| 被忽略的 `config/default-proxy.yaml`、`.image-relay-transports.json` | 实际私人配置 | 本轮未读取内容；不得纳入公开仓库或删除 |

现在访问 `localhost` 会转向 `127.0.0.1`，两个主机本身并不共享浏览器存储。旧 5174 与当前 8888 也不同 Origin。保留迁移和备份机制，不以“统一地址”为理由清旧数据。

自动孤儿媒体清理当前会因 `reference_inventory_unverified` 保留候选，这是一项安全限制；它可能增加磁盘占用，但不能删掉保护条件来获得“清理效果”。

### 7.2 风险及处理建议

1. 本轮扫描 642 个当前跟踪文件无发现；历史扫描 2,201 个 blob 无新增发现，有两项精确绑定的历史演示 URL 例外。扫描不是“绝对无密钥”的证明，不覆盖所有忽略文件、用户存储、插件和运行日志。
2. `client-root-init.tsx` 兼容从 URL 读取 `apiKey` 后移除参数；首次请求、浏览器历史或中间日志仍可能留下记录。后续改为受限输入导入路径，迁移验证前不破坏旧配置。
3. `services/api/model-plugin.ts` 使用 `new Function`，画布插件支持动态加载与运行时接口。同 Origin 的任意脚本不是密钥安全边界；Keychain 能保护持久化明文，但不能保证插件无法调用已授权代理。若用户不用，优先取消任意执行；若保留，需独立隔离和能力白名单，不能宣称已完整安全兼容。
4. 外壳 CSP 限制外连到 self，并禁止 object，但仍允许 inline script/style。该约束不等于对所有画布插件执行完成沙箱隔离，审计时需分别检查不同响应头和实际执行环境。
5. 公共包、私人迁移包、浏览器导出和发布证据必须严格分开；发布产物也要扫描，不能只扫源码。
6. WebDAV、外部 Agent、Gemini 的真实服务测试未覆盖；本阶段不以客户暂不使用为理由伪造通过，也不将其列为精简的阻塞条件。移除相关功能前需测试配置兼容和共享代码。
