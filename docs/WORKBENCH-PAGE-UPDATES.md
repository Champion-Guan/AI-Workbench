# 仅关闭工作台页面的更新规则

2026-10-12 用户明确要求：保存并关闭工作台网址窗口即可更新，浏览器和无关应用无需退出。此规则取代此前“退出全部浏览器”的产品范围，不改变任务、签名、保存或回滚要求。

## 实现

`src/server/workbench-page-census.mjs` 使用固定只读 macOS Apple Events，逐个 PID 枚举 Chrome / Canary / Chromium / Edge / Brave / Safari 的所有窗口和标签，只返回 `http://127.0.0.1:5174` 工作台页面计数。使用 Foundation 原生 Apple Event descriptor 指定进程，避免 JXA `Application(pid)` 在多个相同 bundle 实例中仍然指向同一实例。查询不关闭窗口、不执行页面 JavaScript、不输出其他网站的地址、标题或内容。首次使用时 macOS 可能要求本机浏览器自动化授权；拒绝、超时、异常或不支持的浏览器状态会阻止安装，不推断为零页面。

通用 Electron Renderer、Clash Party、微信、Spotify 与共享 WebKit 服务不再作为工作台页面证据。独立更新器仍需要用户对本次版本确认已保存、生成/Agent/WebDAV全部结束、原生任务账本无未决/失败记录、真实后端冻结和连续许可核验。页面数量为零不单独授予安装权；本机窗口查询不是任意 WebView、第三方插件或远端任务的完整机器库存。使用其他宿主打开工作台时，操作者仍必须关闭它们；不把后台进程数量当作页面数量。

协调器、独立安装调度器、首次接管与更新器自身升级统一使用新检查。旧状态字符串 `awaiting-browser-exit` 为 IPC 兼容保留，界面含义改为等待工作台页面关闭。原有布局、主题与按钮顺序不改。

## 备份边界

安装不迁移、清空、恢复或直接写入 Chrome 数据库，浏览器 Origin 固定不变。浏览器退出时继续完整离线文件备份。Chrome 仍运行时允许生成标为 `stable-byte-copy` 的文件副本，副本及源目录前后所有文件哈希必须一致；源数据变化则失败，部分备份保留。仅跳过 Chrome 根目录三项进程协调符号链接，不忽略其他链接或业务文件。

运行中浏览器的副本仅证明捕获的稳定文件字节，不保证跨数据库事务、未落盘内存或完整冷恢复；明确记录 `automaticBrowserRestoreAllowed=false`，不得将它冒称完整冷备份或自动覆盖原 profile。已有完整冷备份保留。涉及浏览器存储迁移的将来版本必须另做逻辑备份和隔离恢复验证，不能凭此副本继续迁移。

完整回归548项通过，包含真实隔离launchd、首次接管、升级、失败回滚、manager自身升级和冷启动。随后原生PID查询修正及多实例新增用例专项21项通过；Typecheck、Lint（4条既有警告）、Vite构建通过。生产服务仍为v1.0.3/PID10088/原instance，代理正常；三项私人配置哈希保持不变。最终源码查询修正不冒称被之前548项运行覆盖；按变更范围复测专项。

真实 macOS 验证时两个 Chrome 主进程同时运行，Playwright独立测试profile保留57793的QA设置页；增加5174工作台地址测试页（服务返回404，不加载工作台应用/用户数据），原生查询准确返回pages=1并阻止安装。仅关闭该测试页、保留两个Chrome进程和其他网站后返回pages=0，微信/Spotify/Clash Party/WebKit未造成阻断。Chrome用户profile未被脚本编辑，未关闭用户窗口，未发出AI/WebDAV请求。测试设置页的下载、确认弹窗及新文案已检查，取消确认，不执行payload；两个既有logo404不隐藏。

已有正式 v1.0.5 包不可就地修改，标签、公钥和资产不变。此改造需进入新的签名 Stable 版本后才能启用；当前生产仍为原服务，本次没有停止它、操作用户窗口或写入浏览器数据。发布和首次接管须分别完成质量验收与明确版本授权。
